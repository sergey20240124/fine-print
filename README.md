# Мелкий шрифт

Скан рынков предсказаний Polymarket со стороны фаворита и тест правил разрешения
на однозначность. Обновляется сам, раз в сутки, через GitHub Actions.

**Страница живёт по адресу `https://<логин>.github.io/fine-print/`** после первой
публикации (см. установку ниже).

## Зачем это

Идея «страховки на горящий дом» держится на том, что кто-то обязан продавать
защиту ниже её стоимости — рейтинг, валютный коридор, нулевой риск-вес. На рынке
предсказаний такого обязанного продавца нет, и эмпирика указывает в обратную
сторону: по [разбору 313 972 наблюдений на Kalshi](https://www2.gwu.edu/~forcpgm/2026-001.pdf)
контракты дешевле 10 центов теряют более 60% вложенного, а небольшая
положительная доходность встречается только у контрактов дороже 50 центов.

Поэтому страница не ищет дешёвые хвосты для покупки. Она считает экономику
стороны фаворита и заставляет прочитать правила прежде, чем счесть что-либо
находкой. Главная колонка в таблице — не доходность, а «выигрышей на один
проигрыш».

## Установка

```bash
# 1. Создать пустой публичный репозиторий на github.com с именем fine-print
# 2. Из этой папки:
git init
git add .
git commit -m "первый коммит"
git branch -M main
git remote add origin https://github.com/<ВАШ-ЛОГИН>/fine-print.git
git push -u origin main
```

Затем в настройках репозитория: **Settings → Pages → Source: GitHub Actions**.
Это единственный шаг, который нельзя сделать из файлов.

После этого workflow запустится сам — по расписанию в 05:00 UTC (08:00 по Киеву),
а также по кнопке **Actions → daily scan → Run workflow**.

## Что где лежит

| Путь | Роль |
|---|---|
| `index.html` | вся страница: разметка, стили, расчёты. Внешних зависимостей нет, кроме шрифтов Google |
| `data/markets.json` | снимок скана, пересобирается раз в сутки |
| `data/rules-read.json` | **флаги про ясность правил — только здесь и только вручную** |
| `scripts/update.mjs` | тянет Gamma API, пересобирает снимок. Node 18+, без зависимостей |
| `.github/workflows/update.yml` | расписание, коммит изменений, публикация на Pages |

Страница сначала пробует загрузить `data/markets.json`, а если не выходит —
берёт вшитый в `index.html` снимок `MK_FALLBACK`. Поэтому файл открывается
двойным кликом и работает без сервера, просто с данными на день сборки.

## Главное правило этого репозитория

`scripts/update.mjs` **никогда** не выставляет флаги «правила ясны» и «правила
размыты». Он ставит только механические: `дата прошла` (срок из API уже позади)
и `монетка` (обе стороны в диапазоне 0,45–0,55).

Флаги про правила ставит человек, прочитавший поле `description` конкретного
рынка, — в `data/rules-read.json`:

```json
"slug-рынка": {
  "rules": "clear",
  "category": "geopolitics",
  "title_ru": "Короткое название по-русски",
  "прочитано": "2026-09-05",
  "почему": "Назван источник с URL, показатель, порог. Интерпретировать нечего."
}
```

`rules` принимает `clear` или `vague`. Поле `почему` ни на что не влияет
технически и существует, чтобы через полгода было видно основание.

Разделение труда здесь такое: **машина ищет и извлекает свидетельства, человек
выносит вердикт.** Отбор из `scripts/screen.mjs` (см. ниже) вполне справляется с
чтением правил — это извлечение фактов из текста, а не акт суждения, и
утверждать обратное было бы неправдой. Но его результат попадает в
`data/shortlist.json`, а не в `rules-read.json`, и по двум причинам.

Первая: ошибки асимметричны. Назвать размытые правила ясными дорого, обратное —
всего лишь упущенная возможность. Вторая: при двадцати рынках в день никто не
перепроверяет, и невидимый ярлык превращается в основание поставить деньги.
Поэтому шортлист несёт дословные цитаты и процедуру разрешения — чтобы проверка
занимала десять секунд, а не была актом веры.

Описание рынка смотрится так:

```
https://gamma-api.polymarket.com/markets?slug=<slug>
```

## Второй фильтр: отбор случая Бёрри

Нас интересует только положительный класс — рынки, чьи правила разрешаются
механически. Категории «размыто» нет, потому что она ни на что не влияет:
всё, что не прошло, просто не попадает в шортлист.

`scripts/screen.mjs` прогоняет каждый рынок через три стадии. Они независимы
**по конструкции**, и это главное требование: прогнать один и тот же анализ
дважды означало бы удвоить уверенность без роста точности.

| Стадия | Что смотрит | Чем независима | Цена |
|---|---|---|---|
| A. Ворота | форму текста правил | чистый код, никакой модели | 0 |
| B. Источник | мир за текстом: отвечает ли названный URL | сеть, а не текст | 0 |
| C. Резолвер | можно ли написать процедуру разрешения | генерация, а не классификация | вызов API |

Стадия A отсеивает по шести признакам: рынок уже оспаривался в UMA
(`umaResolutionStatuses`), в правилах есть оговорка-лазейка из списка `ESCAPE`,
нет ссылки на машиночитаемый источник, нет сравнения с порогом, не описано
поведение при отсутствии данных, предельная дата в правилах уходит дальше даты
на карточке рынка.

Стадия C требует от модели не вердикт, а **процедуру**: назвать входные данные с
дословными цитатами, перечислить шаги, дать точное сравнение. Каждая цитата
проверяется на вхождение в исходный текст — защита от выдуманных ссылок.
Если хоть один шаг требует оценить намерение или качественный признак, модель
обязана вернуть `executable: false`. Подделать «да, ясно» легко; подделать
работающий резолвер трудно, и в этом весь смысл стадии.

Везде отказ по умолчанию: нет ключа — стадия C не пройдена, а не пропущена;
JSON не разобран — отказ; цитата не найдена — отказ.

### Ключ для стадии C

Settings → Secrets and variables → Actions → New repository secret,
имя `ANTHROPIC_API_KEY`. Опционально переменная `MODEL`, если понадобится
другая модель — по умолчанию `claude-opus-5`.

Без ключа стадии A и B всё равно работают, а шортлист остаётся пустым.

### Как читать результат

Пустой шортлист — нормальный и частый исход. Случай Бёрри редок по
определению: в 2007 году он был один на весь рынок. Если отбор начнёт
стабильно выдавать по три-четыре рынка в неделю, это признак, что пороги
поехали, а не что рынок стал щедрее.

Прохождение трёх стадий означает «стоит потратить время на чтение», а не
«можно ставить». Машина находит и извлекает; вердикт записывает человек в
`data/rules-read.json`.

## Комиссии

Категории на уровне рынка в Gamma API нет, поэтому ставка комиссии определяется
в три шага: ручное переопределение в `rules-read.json`, затем эвристика по
ключевым словам в вопросе, затем консервативный максимум 0,05. Консервативный
означает, что доходность в таблице скорее занижается, чем завышается.

Актуальные ставки площадки на 100 акций при цене 0,50: геополитика — 0 $,
политика/финансы/тех — 1,00 $, экономика/культура/погода — 1,25 $, крипта —
1,75 $. Мейкер не платит ничего. Если площадка их поменяет, правится
константа `FEE` в `scripts/update.mjs`.

## Ограничения

- Корреляция позиций не показана и является главным риском. Двадцать позиций на
  стороне фаворита в одной категории — не двадцать независимых ставок.
- Риск оракула не количественный: разрешение споров идёт голосованием держателей
  токена UMA. Никакая колонка это не отражает, только чтение правил.
- Даты в шапке рынка не равны предельным срокам из правил. Это не исключение, а
  типичный случай — см. разбор рынка про Эфиопию на самой странице.
- Цены — снимок на момент сборки; на тонких рынках исполнимая цена отличается.

## Лицензия и статус

Аналитический инструмент, не инвестиционная рекомендация и не призыв торговать.
Доступность площадки, налоговый режим и требования к верификации различаются по
юрисдикциям и проверяются самостоятельно.
